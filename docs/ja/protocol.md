# ワイヤープロトコル

`type`フィールドで種類を示す、WebSocket上のJSONテキストフレームです。バージョン1。

::: info 手書きではなく生成されます

以下の型は`crates/majin-protocol/src/lib.rs`で定義されています。`pnpm generate:protocol`を実行すると`packages/protocol/src/generated/protocol.ts`が再生成されます。コミット済みの出力と一致しない場合、CIは失敗します。

:::

## クライアントからサーバー

| フレーム | 意味 |
|----|----|
| `{"type":"input","data":"ls\r"}` | キー入力または貼り付けたテキスト。PTYへそのまま書き込みます。 |
| `{"type":"resize","cols":120,"rows":40}` | 新しいビューポートのサイズ。PTYのリサイズはフォアグラウンドプロセスへ`SIGWINCH`も送ります。両軸の値は1〜1000に制限されます。 |
| `{"type":"ping","at":1712345678901}` | 生存確認。サーバーは`at`を`pong`にコピーして返します。 |

## サーバーからクライアント

| フレーム | 意味 |
|----|----|
| `{"type":"ready","protocolVersion":1,"sessionId":"…","shell":"/bin/zsh","cols":80,"rows":24}` | シェル起動直後に1回だけ送信されます。 |
| `{"type":"output","data":"…"}` | デコード済みのPTY出力。xtermへそのまま書き込みます。 |
| `{"type":"exit","exitCode":0}` | シェルが終了しました。直後にソケットも閉じます。 |
| `{"type":"error","code":"…","message":"…"}` | ユーザーに表示する価値のある失敗。下記のコードを参照してください。 |
| `{"type":"pong","at":1712345678901}` | `ping`への応答。 |

### エラーコード

| コード | 原因 |
|----|----|
| `unauthorized` | 有効なセッションCookieがない、またはリクエストのオリジンが拒否された。 |
| `spawn_failed` | 設定されたシェルを起動できなかった。 |
| `session_limit` | `--max-sessions`で指定した数の端末がすでに開いている。 |
| `bad_message` | フレームの検証に失敗した。不正なフレームは致命的エラーにせず破棄される。 |
| `internal` | その他のエラー。 |

## Closeコード

ブラウザーはWebSocketハンドシェイクに失敗したときのHTTPステータスを読めません。そのためサーバーは常にアップグレードを完了してから、クライアントが処理できるコードで切断します。

| コード | 名前 | クライアントの動作 |
|--------|---------------|-------------------------------------------------------|
| `1000` | normal | 停止。セッションは正常に終了しました。 |
| `4001` | unauthorized | ログイン画面に戻る。再接続しても解決しません。 |
| `4002` | sessionLimit | 上限を表示し、サーバーへの接続を繰り返さない。 |
| `4003` | protocolError | 停止。 |
| `4004` | shellExited | 停止。接続ではなくシェルが終了しました。 |

その他のコードは一時的なネットワーク障害として扱い、指数バックオフで再試行します。最大8回、間隔は最大10秒です。

## HTTPエンドポイント

| エンドポイント | 返すもの |
|----|----|
| `GET /api/info` | `{ version, protocolVersion, authRequired }`。公開されており、UIがサインイン前に必要とします。 |
| `GET /api/auth/session` | 現在のCookieに対する`{ authenticated, expiresAt }`。 |
| `POST /api/auth/session` | Bodyは`{ token }`。成功するとセッションCookieを設定し、同じ形を返します。不正なトークンは`401`、レート制限中は`429`です。 |
| `DELETE /api/auth/session` | サーバー側でセッションを無効化し、Cookieを消去します。 |
| `GET /ws` | WebSocketへのアップグレード。1接続につき1つのPTYです。 |

エラーは`{ error, message }`を持ちます。`message`は表示して安全な内容です。

## 検証

ソケットから届くフレームは信頼できません。Rustはデシリアライズ時に未知の形を拒否し、TypeScript側も`packages/protocol/src/codec.ts`のガードを使って端末に届く前に検証します。不正なフレームは破棄してログに記録するだけで、致命的にはしません。バグのあるクライアントが他人のシェルを終了させられないようにするためです。
