# セキュリティ

このプログラムは対話的なシェルを提供します。到達して認証できる人は、実行ユーザーができることをすべて実行できます。

::: danger まずここから

`majin`はデフォルトで`127.0.0.1`にバインドします。このデフォルトには理由があります。別のマシンから到達可能にする場合は、どこかから`--host 0.0.0.0`をコピーした結果ではなく、前段にTLSを置くことを含めて意識的に決めてください。

:::

## サインインの仕組み

1. 起動時に、サーバーは`MAJIN_TOKEN`のトークンを使うか、192ビットのランダムなトークンを生成して表示します。
2. クライアントはトークンを`POST /api/auth/session`へ送ります。サーバーはSHA-256ダイジェストを定時間比較するため、トークンそのものも長さも比較処理から漏れません。
3. 成功すると、サーバーは256ビットのランダムなセッションIDを作成し、メモリ上に保持して、`HttpOnly; SameSite=Strict` Cookieとして返します。
4. WebSocketのアップグレードはそのCookieで認証されます。ブラウザーが自動的にCookieを付けます。

### セッションをメモリに保持する理由

管理や漏えいの心配がある署名鍵は不要で、サインアウトした瞬間にセッションを無効化でき、再起動ですべてを無効にできます。シェルを提供するプロセスでは、再起動でセッションを失うことが正しいトレードオフです。

### トークンをURLクエリに置かない理由

クエリ文字列はプロキシログ、サーバーのアクセスログ、ブラウザー履歴、`Referer`ヘッダーに残ります。シェルへのアクセス権を与えるトークンをこれらに残すべきではないため、サーバーはURLクエリからトークンを受け付けません。

代わりに、起動バナーは`#token=…`という*フラグメント*付きリンクを表示します。フラグメントはサーバーへ送信されないのでログに到達しません。ページはそれを読み取ってCookieと交換し、他の処理より先に`history.replaceState`でアドレスバーから消します。

::: info 残るトレードオフ

フラグメントは消去されるまでアドレスバーに表示され、ローカルのブラウザー履歴に残る可能性があります。環境上それが問題になる場合は、`MAJIN_TOKEN`を自分で設定し、リンクではなくログインフォームへ貼り付けてください。

:::

## クロスサイトリクエストフォージェリ

Cookieで認証するWebSocketには注意が必要です。チェックがなければ、ユーザーが開いたどんなページでも`localhost`へソケットを開き、ブラウザーがCookieを自動的に付けることでシェルを取得できてしまいます。

2つの防御策を意図的に重ねています。

- セッションCookieの`SameSite=Strict`。ブラウザーがクロスサイトリクエストにCookieを送るのを止めます。
- アップグレード時の明示的な`Origin`チェック。同一オリジンのリクエストは通し、それ以外は`--allowed-origin`に列挙されたものだけを許可します。`Origin`ヘッダーがないリクエストは許可します。これはブラウザー以外のクライアントであり、勝手に送られるCookieを悪用できないためです。

## レート制限

1つのアドレスから1分以内に10回サインインに失敗すると、正しいトークンを使った場合も含めて、そのアドレスを残りの期間ロックします。トークンは192ビットのランダム値なので、これは攻撃者とシェルの間に立つ主な防御ではなく、ノイズとログのスパムを止めるためのシンプルな仕組みです。

## サーバーが提供しないもの

| 提供しないもの | 代わりにすること |
|----|----|
| TLS | Caddy、nginx、クラウドロードバランサーなどで前段終端する。通常のHTTPではセッションCookieもキー入力も平文で送られます。 |
| 複数のユーザーやアカウント | トークンとシェルのIDは1つだけです。ユーザーごとのアクセスが必要なら、認証プロキシを前段に置き、インスタンスを分けて実行します。 |
| サンドボックス | シェルはサーバーを起動したユーザーとして、そのユーザーの完全な環境で動作します。望ましくない場合は権限を制限したアカウントかコンテナ内で実行します。 |
| セッション内容の監査ログ | 接続とライフサイクルイベントは記録しますが、キー入力と出力は記録しません。 |

## デプロイチェックリスト

- HTTPSで配信し、プロキシが`X-Forwarded-Proto`を送らない場合は`MAJIN_SECURE_COOKIE=1`を設定する。
- `MAJIN_TOKEN`を明示的に設定し、再起動後も維持できるようにする。共有ログに表示されることも防げる。
- バインドアドレスをできるだけ狭く保つ。`0.0.0.0`へのバインドより、ループバックとリバースプロキシを優先する。
- 専用の権限のないユーザーとして実行し、rootでは実行しない。
- UIがサーバーと異なるオリジンから配信される場合にだけ`--allowed-origin`を設定する。
- 共有マシンでは、デフォルトの12時間より`--session-ttl-minutes`を短くする。

## デスクトップ版

上記の内容はデスクトップ版には当てはまりません。ポートもトークンもCookieもありません。PTYにはTauri IPCで接続し、コマンドを呼び出せるのはそのプロセス内のウィンドウだけです。脅威モデルは、インストールする他の端末エミュレーターと同じです。
